# 牛牛一家人音频故事工作室

本项目采用音频优先流程：先把故事和最终音频做好并完整试听，再围绕这份已确认 MP3 生成最多 10 张配图，最后渲染视频。

## 启动

双击 `启动工作室.bat`（会自动起服务并打开浏览器），或在项目根目录执行：

```powershell
D:\new project\.python\python.exe -m studio.server --port 8000
```

浏览器打开 `http://127.0.0.1:8000`。停止服务用 `停止服务.bat`。

前端没有独立工程：`studio/static/` 下三个静态文件由后端一起发出来，不需要 npm。

## 唯一正式流程

1. 输入点子、不完整故事或较完整故事，并选择故事类型。
2. 根据系列圣经生成故事，编辑后确认母稿。
3. **脚本改编（两层分工的关键一步）**：把母稿交给 AI 标注“哪句是谁说的”，
   并把一部分对白转述成旁白，再由程序机械校验，得到旁白主导的音频脚本。
4. 审核并冻结音频脚本。
5. 使用“设置 → 声音”中的当前家庭声音方案合成最终 MP3。
6. 从头试听 MP3，确认后冻结音频和时间轴。
7. 根据冻结时间轴规划视觉节拍（4/6/8/10 张可选，默认 6，含封面节拍）。
8. 生成并检查配图，选择封面模板。
9. 使用原 MP3、配图和字幕渲染视频，禁止重新配音。

故事、音频、图片任一上游内容改变后，下游产物自动失效，必须重新确认。

## 两层分工：故事层只管好看，脚本层负责能配音

这是本项目最重要的一条设计。两层各有自己的验收标准，互不越界。

### 第一层：故事创作（`pipeline/story_gen.py`）

- **主要依据是系列故事圣经**（`stories/牛牛一家人_儿童故事创作圣经_V1.0.md`），
  它规定人物、世界观、风格、开头与结尾、幽默与情绪、长度与节奏。
  圣经是必需项：没配、路径写错或文件为空都**直接报错**，不会静默降级成“没有系列味道的裸写”。
- 全局提示词只保留所有儿童故事都成立的底线：事实自洽（数字/年龄算得通）、
  孩子听得懂、输出格式。**不重复圣经已经规定的内容**——重复会让通用条款压过圣经。
- 长度按圣经《十六、长度与节奏》：点子目标 600~800 字，硬范围 500~900 字；
  较完整的稿子优先忠实保留原篇幅，不为凑字数扩写。
- **这一层不承担音频形式要求**：不要求“每句台词前加引导语”，不要求旁白比例。
  这些由下一层解决。

### 第二层：脚本改编（`pipeline/audio_annotator.py` + `pipeline/audio_script.py`）

- **AI 标注**：把母稿交给模型，逐句判断说话人；语义判断，不看写法。
  所以 `“……”爸爸问。`（引导语在后）、`指着牛牛：“……”`（用动作代替“说”）都能正确识别。
- **AI 改写体裁**：模型有权把一部分对白**转述成旁白**（意思不变），
  这是“旁白占多数”的实现手段。
- **程序只做机械校验**：标注必须覆盖全部引号、说话人必须在人物表里；
  改写不许夹带引号、不许膨胀成新情节；母稿被改写的位置换成新句子后逐字比对，
  因此改写只能是“同一位置替换”，不可能凭空增删内容。
- 标注失败或模型返回坏 JSON 时**整体回退**到语法推断，不会让流程崩掉。

**为什么不让程序猜说话人**：说话人是语义标注，信息不在字符串里。历史上用正则从母稿
反推说话人，遇到后置引导或动作用词就失败，而失败又被当成致命错误，于是整条出片任务
作废、重写整篇故事（一次 5 分钟）。实测五次批量失败 100% 都是这一类。

## 创作规则

- 系列故事内核来自系列记录的 `series_bible` 文件，**该文件是必需的**。
- 系列圣经不控制音色、配乐和旁白比例。
- 旁白/对白比例、对白长度和连续对白限制统一定义在 `pipeline/story_policy.py`，
  由脚本层通过“把对白转述成旁白”来达成；低于底线的一半才判为“素材不适合做音频故事”。
- 对白引导语、台词长度、连续对白这类**听感**问题在脚本层以提示形式报告，不再拦截流程。
- 结尾在真实落点出现后立即停止，不强制固定两拍或家长回应。
- 想象故事只使用用户明确给出的尺度，不自动发明三倍、八倍或临时物品比喻。

## 音频配置

声音方案在前端“设置 → 声音”维护：

- 主方案：豆包语音 2.0。
- 备用方案：Edge 旁白/爸爸 + 千问家庭角色。

暂停、尾隙、BGM 类型和音量由 `config.yaml` 的 `audio_story` 配置控制。Studio 会用系列的 `bgm_mood` 覆盖默认类型。系统不会自动添加固定结尾音效。

## 图片与视频

- 配图只能在最终音频试听确认后生成。
- 图片数量可选 4 / 6 / 8 / 10 张（默认 6，可在设置中心改默认值）。第一张视觉节拍用于封面。
- 出图后自动质检：一次调用同时核对【角色是否与定妆照一致】和【画面里有没有此刻还不该出现的东西】。
  角色不一致会重画（最多 3 次）；画面与旁白疑似矛盾只写进日志提醒，不阻断出图（视觉模型在这种
  判断上会抖动，拿它拦流程会让人出不了片）。质检没配 key 或调用失败时不会重画，直接报出原因。
- 视频渲染只接受已确认 MP3 和对应时间轴摘要，画面只复用已生成的配图，绝不重新配音。


测试覆盖故事输入类型、故事类型、统一音频政策、对白引导、结尾、事实表、音频冻结、试听确认、

## 主要目录

- `pipeline/`：正式故事、音频、视觉规划和渲染模块。
- `studio/`：FastAPI 工作室和前端。
- `stories/`：系列圣经、母稿、事实表和冻结音频脚本。
- `assets/character_refs/`：角色定妆参考图。
- `assets/bgm/`：按 mood 分类的配乐。
- `output/audio_story/`：最终 MP3 和时间轴。
- `output/images/`：视觉节拍配图。
- `output/videos/`：最终视频。
